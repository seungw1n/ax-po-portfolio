# 도메인 특화 데이터 콘텐츠 분석 서비스

> 상권·부동산 데이터를 가공해 "의사결정에 바로 쓰이는 콘텐츠"로 만드는 분석 서비스.
> 본 문서는 Sanity CMS의 `project` 스키마(`sections[]`) 구조에 맞춰 작성되어,
> 그대로 스튜디오에 옮겨 담을 수 있습니다.

---

## 메타 정보 (CMS 상단 필드)

| 필드 | 값 |
|------|-----|
| **title** (프로젝트 제목) | 상권·부동산 데이터 콘텐츠 분석 서비스 |
| **summary** (요약) | 공공·민간 상권/부동산 데이터를 수집·해석해, 창업·투자 의사결정에 바로 쓰이는 리포트형 콘텐츠로 전환한 도메인 특화 분석 서비스. |
| **domainTags** (도메인) | `상권분석` `부동산` `데이터` `콘텐츠` |
| **organizationTags** (소속) | `개인 프로젝트` *(실제 소속으로 교체)* |
| **본인 역할** | 고객 니즈 파악 · 데이터 분석 · 콘텐츠 작성 |

> 아래 각 절은 CMS의 한 **섹션(section)** 에 1:1로 대응합니다.
> 제목 옆 대괄호는 `sectionType` 드롭다운 값입니다.

---

## 1. 왜 이 서비스를 만들었나 — [배경]

**한 줄 요약:** 데이터는 공개되어 있지만, 정작 결정을 내려야 하는 사람은 그 데이터를 읽지 못한다.

- 상권/부동산 데이터(매출 추정, 유동인구, 임대 시세, 공실률 등)는 공공데이터포털·지자체·민간 플랫폼에 흩어져 공개되어 있다.
- 그러나 예비 창업자·소상공인·투자자는 **원천 데이터를 직접 해석할 시간도 역량도 없다.** 숫자를 "그래서 여기 들어가도 되는가"라는 답으로 바꿔주는 단계가 비어 있었다.
- 기존 상권 리포트는 ① 지표 나열에 그치거나 ② 광고성 결론으로 흘러, **중립적이고 맥락이 있는 해석 콘텐츠**에 대한 수요가 있었다.

**이 섹션에서 보여줄 것**
- 시장의 정보 비대칭 구조(데이터 보유자 ↔ 의사결정자)
- 서비스가 채우려는 빈칸: *데이터 → 해석 → 콘텐츠*

---

## 2. 누가, 무엇을 필요로 하는가 — [실험]

> 역할 핵심 ①: **고객 니즈 파악**

서비스의 출발점은 "어떤 데이터를 보여줄까"가 아니라 **"고객이 어떤 결정 앞에서 막히는가"** 였다.

**타깃별 핵심 질문(Job To Be Done)**

| 고객군 | 결정 상황 | 진짜 알고 싶은 것 |
|--------|-----------|-------------------|
| 예비 창업자 | "이 동네에 카페를 열까?" | 유동인구의 질, 경쟁 밀도, 임대료 대비 매출 여력 |
| 소상공인 | "지금 자리를 옮길까?" | 상권 쇠퇴/성장 추세, 배후 수요 변화 |
| 소액 투자자 | "이 매물 수익률이 맞나?" | 공실 리스크, 임대 시세 적정성, 개발 호재 |

**니즈 검증 방법**
- 타깃 인터뷰/설문으로 "결정에 쓰는 정보 vs. 못 구해서 포기한 정보" 구분
- 검색 키워드·커뮤니티 질문 분석으로 *실제로 검색되는 언어* 수집 (예: "권리금 적정한지", "여기 망한 자리인지")
- 가설: **사람들은 지표가 아니라 '확신'을 사고 싶어 한다** → 콘텐츠 톤·구성의 기준이 됨

**산출물:** 고객군 × 결정 시나리오 매트릭스, 콘텐츠가 답해야 할 질문 리스트

## 3. 무엇이 어려웠나 — [문제]

데이터에서 콘텐츠까지 가는 길에는 3가지 병목이 있었다.

1. **데이터 신뢰성 문제**
   - 출처마다 매출 추정/유동인구 산정 기준이 다름 → 단순 비교 시 왜곡
   - 시점 불일치(분기 데이터 vs. 월 데이터), 행정동/법정동 경계 불일치

2. **해석의 일관성 문제**
   - 같은 지표라도 상권 성격(주거형·오피스형·관광형)에 따라 의미가 정반대
   - 분석자의 주관이 들어가면 콘텐츠 신뢰도가 떨어짐 → **판단 기준의 규칙화** 필요

3. **전달의 문제**
   - 전문 지표를 비전문가가 읽게 만들어야 함 → "공실률 8%"가 아니라 "10곳 중 1곳이 비어 있어요"

**문제 정의 한 줄:** *흩어지고 기준이 다른 데이터를, 일관된 해석 규칙으로 묶어, 비전문가가 결정에 쓸 수 있는 언어로 바꾸는 것.*

## 4. 어떻게 데이터를 다뤘나 — [시스템 설계]

> 역할 핵심 ②: **데이터 분석**

분석 파이프라인을 "수집 → 정제 → 지표화 → 해석"의 4단계로 설계했다.

```
[수집]                [정제]              [지표화]            [해석]
공공데이터포털    →   기준 통일       →   상권 점수 산출  →   규칙 기반 코멘트
지자체 상권API        (행정동 매핑)       (성장성/안정성/      (성격별 임계값)
민간 시세데이터        시점 정규화         경쟁강도/배후수요)
```

**1) 수집**
- 공공데이터(소상공인진흥공단 상권정보, 국토부 실거래가), 지자체 상권 API, 민간 시세
- 정기 업데이트 주기 정의(분기/월) 및 출처 메타데이터 기록

**2) 정제**
- 행정동 ↔ 법정동 ↔ 상권 경계 매핑 테이블 구축
- 시점 정규화(최근 N분기 이동평균)로 일시적 노이즈 제거
- 결측/이상치 처리 규칙 명문화

**3) 지표화** — 4개 핵심 축으로 압축
| 축 | 대표 지표 | 의미 |
|-----|-----------|------|
| 성장성 | 매출/유동인구 추세 | 상권이 뜨는가, 지는가 |
| 안정성 | 공실률, 폐업률 | 리스크가 큰가 |
| 경쟁강도 | 동종 업종 밀도 | 레드오션인가 |
| 배후수요 | 거주/직장 인구 | 손님이 어디서 오는가 |

**4) 해석(규칙화)**
- 상권 성격별 임계값 설정 → "공실률 8%"가 주거형엔 경고, 관광형엔 정상
- 분석자 주관 대신 **규칙이 1차 코멘트를 생성**하고, 사람이 검수·보강

## 5. 콘텐츠를 어떻게 구성했나 — [화면 설계]

> 역할 핵심 ③: **콘텐츠 작성**

지표를 "읽히는 리포트"로 바꾸는 콘텐츠 포맷을 설계했다.

**리포트 1편 구성(템플릿)**
1. **결론 먼저** — "한 줄 진단" (예: *성장 중이지만 경쟁이 빠르게 붙는 상권*)
2. **3대 근거** — 핵심 지표 3개를 비유로 번역 ("10곳 중 1곳 공실")
3. **누구에게 맞나** — 업종/타깃별 적합도
4. **주의할 점** — 리스크와 반대 시그널까지 균형 있게
5. **데이터 출처·시점** — 신뢰를 위한 투명성 고지

**작성 원칙**
- 지표가 아니라 **결정**을 말한다 ("들어가도 되는가"에 답)
- 좋은 점·나쁜 점을 함께 → 광고가 아닌 **중립적 해석**
- 전문 용어는 반드시 일상어로 1회 풀어줌
- 같은 데이터, 다른 고객 → **재가공 가능한 모듈형** 문단 설계

**산출물:** 콘텐츠 템플릿, 용어 번역 사전, 톤앤매너 가이드

---

## 6. 더 나은 표현을 찾는 과정 — [A/B 테스트]

콘텐츠가 실제로 "읽히고 신뢰받는지"를 검증했다.

| 비교 항목 | A안 | B안 | 관찰 지표 |
|-----------|-----|-----|-----------|
| 제목 | 지표형("공실률 8%") | 결론형("지금은 신중할 때") | 클릭률 |
| 도입부 | 데이터 요약 먼저 | 결론 먼저 | 체류시간/이탈 |
| 근거 표현 | 숫자 그대로 | 비유로 번역 | 끝까지 읽은 비율 |

**검증 가설**
- *결론을 먼저 제시한 콘텐츠가 끝까지 읽힌다* (역피라미드 구조)
- *비유로 번역한 지표가 신뢰·이해도를 높인다*

**해석 방법:** 정량(체류·이탈·완독률) + 정성(피드백, "도움이 됐다" 응답)을 함께 보고 콘텐츠 가이드에 반영.

## 7. 무엇을 얻었고, 무엇을 배웠나 — [결과/회고]

**결과 (예시 — 실제 수치로 교체)**
- 흩어진 N개 출처 데이터를 단일 분석 파이프라인으로 통합
- 상권 1곳당 리포트 작성 시간 **△일 → △시간**으로 단축 (템플릿·규칙화 효과)
- 콘텐츠 완독률/재방문 등 핵심 지표 개선

**배운 점**
- **데이터 분석의 끝은 "숫자"가 아니라 "결정"이다.** 고객의 질문에서 출발하지 않은 지표는 콘텐츠가 되지 못한다.
- **해석을 규칙화하면 품질이 일정해진다.** 주관에 기대지 않는 임계값 설계가 신뢰의 핵심이었다.
- **번역이 곧 가치다.** 같은 데이터라도 "비전문가의 언어"로 옮기는 순간 의사결정 도구가 된다.

**다음 단계 (To-do)**
- 지역/업종 확장 시 임계값 자동 보정
- 사용자 맞춤(업종·예산 입력 → 개인화 리포트)
- 데이터 출처 추가 및 업데이트 자동화

### 작성 가이드 (이 문서를 CMS로 옮길 때)
- 각 `## n.` 절 = CMS `section` 1개. **섹션 제목**과 **sectionType**(대괄호 값)을 그대로 사용.
- 표/코드블록은 본문(block)으로, 다이어그램·스크린샷은 `sectionImage`로 첨부.
- *기울임 표시*된 부분(수치, 소속 등)은 실제 사실로 교체 필요.
