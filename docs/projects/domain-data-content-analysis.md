# 데이터 숙련도가 낮은 사용자의 주도적 의사결정을 위한 데이터 콘텐츠 & 분석 도구

> 분석 도구의 기능을 늘리는 대신, "이 데이터로 당신의 이 결정을 푼다"를 **콘텐츠로 먼저 보여주는** 동선을 설계해
> 홈페이지 유입 → 서비스 활성화 전환을 만든 PO 프로젝트.
> 본 문서는 Sanity CMS `project` 스키마(`sections[]`)에 1:1로 옮길 수 있게 작성했습니다.

## 1. 기능을 더해도 사용자는 움직이지 않았다 — [배경]

**한 줄 요약:** 빅밸류는 상권·부동산 분석 도구를 만들었지만, 정작 유입된 잠재고객은 데이터를 보고도 "그래서 내 비즈니스에 뭘 하라는 거지?"에서 멈춰 있었다.

- 빅밸류는 상권·부동산 데이터를 다루는 B2B 분석 서비스를 운영한다. 홈페이지로 소상공인·부동산 중개업자 등 잠재고객이 꾸준히 유입됐다.
- 그러나 이들은 **원본 데이터(매출 추정·유동인구·시세 등)를 봐도 자기 비즈니스 문제를 어떻게 푸는지 떠올리지 못했고**, 이것이 분석 도구 사용으로 이어지지 않았다.
- 통상의 대응은 "기능을 더 쉽게, 더 많이"였다. 하지만 나는 이 문제를 **기능의 문제가 아니라 '가치 인식'의 문제**로 봤다. 데모를 아무리 매끄럽게 만들어도, 사용자가 그 데모를 *자기 결정*으로 번역하지 못하면 전환은 일어나지 않는다.

**이 프로젝트의 출발 관점**
> 단순 기능 개선을 넘어 **분석 경험의 방향성 자체를 설계**하는 문제로 정의했다.

## 2. 사용자는 '기능' 앞이 아니라 '가치' 앞에서 멈춘다 — [문제]

> PO로서 가장 먼저 한 일: 막연한 "전환이 낮다"를 **정량 근거가 있는 문제**로 좁히는 것.

**데이터 분석 퍼널 (GA4 사용자 행동 분석)**

| 단계 | 관측값 | 진단 |
|------|--------|------|
| 진입 | 홈페이지 진입 사용자의 **86%가 첫 화면에서 이탈** | 가치 제안이 첫 화면에서 전달되지 않음 |
| 탐색 | 데이터 카탈로그 페이지 **평균 체류 38초** | 데이터를 봐도 '쓸 거리'로 인식하지 못함 |
| 분석 진입 | **'Area 선택' 단계 이탈률이 큼** | "어느 지역을 왜 봐야 하는지" 동기 부재 |
| 전환 | **회원가입 전환율 1.6%** | 가입할 이유를 못 느낌 |

**타깃 (B2B 의사결정자)**
- **직군:** 부동산 중개업자, 상권 분석가, 소상공인, 시행사 담당자
- **공통점:** 데이터 숙련도 낮음 — SQL·BI 도구 직접 사용 경험 거의 없음
- **의사결정 영역:** 입지 선정, 상권 분석, 매물 가격 협상, 사업 확장 판단

**결정적 단서 — CS 데이터**
> 전체 CS의 **30%가 "가치 인식 부재"로 분류**됐다. 이는 사용자가 분석 도구 앞에서 *"어떤 데이터를 봐야 내 비즈니스 문제를 풀 수 있는지"* 떠올리지 못하는 상태임을 의미한다.

**문제 정의 한 줄**
> *데이터 숙련도가 낮은 도메인 종사자는, 분석 도구의 기능 데모를 봐도 자기 비즈니스 의사결정에 어떤 가치를 얻을 수 있는지 떠올리지 못한다.*

→ 즉 병목은 **기능의 부족이 아니라 '데이터 ↔ 내 결정' 사이의 번역 부재**다.

## 3. 그래서, 기능 개선이 아니라 콘텐츠였다 — [실험]

> 이 프로젝트의 핵심 의사결정: **"기능을 더할 것인가, 가치를 보여줄 것인가."**

### 왜 콘텐츠인가 — "콘텐츠는 수단이다"

기능을 더 쉽게 만드는 접근은 *"도구를 어떻게 쓰는가"* 를 가르친다. 하지만 우리 사용자가 막힌 지점은 사용법이 아니라 **"이 도구로 내 무엇을 풀 수 있는가"** 였다. 그래서 해법을 이렇게 뒤집었다.

- **콘텐츠는 목적이 아니라 서비스로 가는 수단이다.** "카페 자리 고를 때 월세가 매출 대비 적정한지 이렇게 본다"를 콘텐츠로 먼저 보여주면, 사용자는 그제야 *자기 결정*을 떠올리고 도구를 직접 써본다.
- **서비스와 콘텐츠의 타깃 고객은 동일하다.** 그래서 콘텐츠는 단순 마케팅이 아니라, 서비스 활성화 동선의 첫 단계로 설계될 수 있었다.
- 기능 개선이었다면 "더 나은 차트"에 그쳤겠지만, 콘텐츠는 **"왜 이 데이터를 봐야 하는가"라는 동기 자체를 만든다.** 이것이 86% 이탈의 진짜 해법이라고 판단했다.

### 검증 방식 — PO팀 자체 프로토타입

> **목표:** 홈페이지→서비스 전환 가설을, 개발 리소스 투입 전 **PO팀 자체 프로토타입으로 검증**해 도메인 콘텐츠 동선이 작동하는지 *정량으로* 입증한다.

### KPI 설계 — 큰 지표를 쪼갠 작은 지표들

전환이라는 큰 지표를, 퍼널 단계별로 움직일 수 있는 작은 선행 지표로 분해했다.

| 단계 | KPI | 목표 |
|------|-----|------|
| **진입** | 콘텐츠 → 서비스 클릭률 | 15% 이상 |
| **활성화** | 서비스 분석 1회 이상 실행률 | 50% 달성 |
| **유지** | 코호트 D7 리텐션 | 20% 이상 |

## 4. 머릿속 계산을 시스템이 먼저 꺼내 보여준다 — [시스템 설계]

> 핵심 인사이트: **원자 지표를 그대로 노출하면 안 된다.**

**파생 지표 설계 — 활용 시도를 트리거하는 장치**

매출·유동인구·시세 같은 원자(raw) 지표를 그대로 보여주면, 숙련도 낮은 사용자는 해석하지 못한다. 그래서 **도메인 종사자가 실무에서 이미 머릿속으로 계산하고 있는 파생 지표를 시스템이 먼저 정의해 보여주는** 방식으로 뒤집었다. 사용자가 평소 어림짐작하던 값을 시스템이 정확히 제시하는 순간, "그럼 내 자리는?" 하며 활용 시도가 트리거된다.

- 상권·부동산 도메인 특화 **파생 지표 5개**를 설계 (예: **'월세 효율'** — 임대료 대비 매출 여력)
- *(나머지 4개 지표명·정의를 실제 값으로 채울 것: 예) 경쟁 밀도, 배후 수요 강도, 상권 성장성, 공실 리스크 등)*
- 각 지표는 "사용자가 어떤 결정을 할 때 보는가"에서 역산해 정의 — 지표 자체가 아니라 **결정 시나리오**가 설계 기준

**콘텐츠 제작 자동화 에이전트**

지표를 발굴하고 그것을 쉬운 콘텐츠로 푸는 작업은 반복적이고 병목이었다. 이를 자동화하는 에이전트를 구축했다.

- 데이터에서 **지표 후보를 발굴**하고, 도메인 톤에 맞는 **콘텐츠 초안을 작성**하는 파이프라인
- 사람은 검수·보강에 집중 → **콘텐츠 제작 시간 60% 절감**, 14개 콘텐츠를 빠르게 배포할 수 있던 기반

## 5. 콘텐츠에서 서비스로 끊김 없이 — [화면 설계]

> 콘텐츠는 읽히는 것으로 끝나면 실패다. **반드시 서비스 실행으로 이어지는 동선**으로 설계했다.

**인바운드 콘텐츠 1편 구조 (전환 동선 내장)**
1. **사용자의 결정 질문으로 시작** — "이 동네 카페, 월세가 매출 대비 적정한가?"
2. **파생 지표로 답을 시연** — '월세 효율'을 실제 지역 데이터로 보여줌
3. **비유로 번역** — "공실률 8%"가 아니라 "10곳 중 1곳이 비어 있어요"
4. **"당신 지역으로 직접 보기" CTA** — 같은 분석을 서비스에서 바로 실행 (콘텐츠→서비스 연결점)

**인사이트 루프 — 콘텐츠로 알게 된 사용자로 서비스를 고도화**

콘텐츠 반응 데이터는 사용자를 더 깊이 이해하는 창이기도 했다.

> 콘텐츠 반응에서 **카페 창업에 대한 관심이 두드러진다**는 인사이트 → 데이터 대시보드의 **시작 주제를 '카페 창업'으로 설정**해 서비스 진입 자체를 사용자 관심에 맞춰 고도화.

→ 콘텐츠가 마케팅을 넘어 **제품 방향을 정하는 사용자 리서치 채널**로 작동했다.

## 6. 어떤 콘텐츠가 전환을 만드는가 — [A/B 테스트]

배포한 **14개 콘텐츠**를 통해 "무엇이 서비스 전환으로 이어지는가"를 검증했다.

| 비교 축 | 변형 | 관찰 지표 |
|---------|------|-----------|
| **콘텐츠 주제** | 업종형(카페 창업) vs 지역형(OO동 상권) | 콘텐츠→서비스 클릭률 |
| **콘텐츠 타입/유형** | 가이드형 vs 사례형 vs 체크리스트형 | 완독률·CTA 클릭률 |
| **지표 표현** | 원자 지표 그대로 vs 파생 지표·비유 번역 | 서비스 분석 실행률 |

**검증 가설**
- *사용자의 결정 질문에서 시작한 콘텐츠가 서비스 실행으로 더 잘 이어진다.*
- *파생 지표를 비유로 번역할 때 "직접 해보고 싶다"는 행동이 트리거된다.*

**해석 방법:** 정량(클릭률·실행률·리텐션) + 정성(CS·피드백)을 함께 보고, 전환이 높은 주제·유형을 다음 콘텐츠와 대시보드 기본값에 반영.

## 7. 결과와 배운 점 — [결과/회고]

**KPI 대비 결과** *(기간: 3개월)*

| KPI | 목표 | 결과 |
|-----|------|------|
| 콘텐츠 → 서비스 **전환율** | 클릭률 15% 이상 | **27% 달성** |
| 서비스 **리텐션** | D7 리텐션 20% 이상 | **기존 대비 65% 증가** |
| 콘텐츠 **제작 시간** | — | **60% 절감** (자동화 에이전트) |
| 배포 | — | 도메인 특화 지표 **5개** 설계 · 인바운드 콘텐츠 **14개** 배포 |

*(활성화 KPI '서비스 분석 1회 이상 실행률 50%' 결과 수치도 채워 넣을 것)*

**배운 점**
- **전환이 낮을 때 답이 늘 '기능 추가'는 아니다.** 진짜 병목은 '데이터 ↔ 내 결정'의 번역 부재였고, 그건 기능이 아니라 콘텐츠로 풀리는 문제였다. 문제를 올바른 층위에서 정의하는 것이 PO의 첫 일이었다.
- **콘텐츠는 수단이다.** 서비스와 같은 타깃을 향할 때, 콘텐츠는 마케팅을 넘어 활성화 동선이자 사용자 리서치 채널이 된다 (카페 창업 인사이트 → 대시보드 고도화).
- **지표는 노출이 아니라 트리거다.** 원자 지표가 아니라 사용자가 이미 머릿속으로 계산하던 파생 지표를 먼저 제시할 때 활용 시도가 시작된다.

**다음 단계 (To-do)**
- 전환이 높은 콘텐츠 유형을 템플릿화해 자동화 에이전트에 반영
- 콘텐츠 반응 → 대시보드 기본값 개인화(업종·지역) 루프 자동화
- 파생 지표를 지역·업종 확장에 맞춰 자동 보정

### 작성 가이드 (이 문서를 CMS로 옮길 때)
- 각 `## n.` 절 = CMS `section` 1개. **섹션 제목**과 **sectionType**(대괄호 값, 스키마 드롭다운과 일치)을 그대로 사용.
- 표/다이어그램은 본문(block)으로, GA4 퍼널 그래프·대시보드 캡처·콘텐츠 예시는 `sectionImage`로 첨부하면 설득력이 크게 오른다.
- *기울임* 표시된 부분(지표명, 기간, 활성화 결과 수치 등)은 실제 값으로 교체 필요.
